# 数有方 · 研习空间

数有方是面向个人自主学习的课程学习平台。以导入资料为起点，将课程、章节阅读、AI 问答、笔记、练习、错题复习和学习计划串联起来。界面采用纸色、墨色与少量朱红、青绿，保持统一的中式研习风格。

本项目包含用户端、管理端和后端服务，学习数据主要存储在 MySQL 与后端文件目录中。

## 本机访问地址

| 服务     | 地址                          | 说明                         |
| -------- | ----------------------------- | ---------------------------- |
| 用户端   | <http://127.0.0.1:5173/>      | 学习首页、课程与学习工具     |
| 管理端   | <http://127.0.0.1:5173/admin> | 需要管理员账号登录           |
| 后端 API | `http://127.0.0.1:8005/api`   | 为前端提供接口，不是网页首页 |

以上是当前本机开发配置。访问网页前，需要启动 MySQL、后端和前端。

## 已有功能

### 用户端

- **学习首页**：继续学习、今日任务、最近学习、学习记录与连续学习情况。
- **我的课程**：导入资料创建课程，管理章节、资料、课程封面和章节配图。
- **章节学习**：阅读章节内容与原资料，修正章节文字，生成章节总结，记录阅读进度与书签。
- **学习助手**：选择课程或章节范围进行问答，管理研习对话，将回答加入笔记。
- **笔记与练习**：编辑学习笔记，生成和完成章节练习，查看答题记录。
- **错题复习**：管理错题、掌握状态与复习安排。
- **学习计划**：制定学习计划，调整任务与日期，记录任务进度。
- **账号与设置**：修改个人资料、调整字体与模型偏好、管理配图、切换账号及退出登录。

AI 整理、问答和生图需要相应服务可用。普通课程管理与已有学习内容不依赖每次调用 AI。

### 管理端

- **管理首页**：查看用户、课程、资料和生成任务概况，核查存储状态。
- **用户管理**：查询用户、查看学习数据统计，停用、恢复或注销学习账号。
- **课程与资料查询**：筛选和查看详情，暂停或恢复内容，修复资料预览。
- **AI 任务**：查看生成任务、诊断信息，按任务状态执行取消或重试。
- **公告管理**：编辑和发布平台公告。
- **服务状态**：配置文字 AI、邮件及章节配图服务，检查连接与查看检查结果。
- **运行设置与备份**：管理运行限制，创建、验证、下载及删除历史备份。
- **操作日志**：检索管理操作及处理结果。

停用可以恢复；注销不可恢复，会撤销登录权限并解绑邮箱。注销后账号名称和学习记录仍保留供管理核查，并非清空该用户的全部数据。管理员账号不能通过用户管理中的注销功能处理。

## 日常启动：一键方式

当前本机项目目录：

```text
E:\CodexProjects\AI-Course-Learning-Platform\math-auth-app
```

1. 确认 MySQL 服务已经启动。
2. 打开项目目录，双击 `start-site.cmd`。
3. 等待约 10～30 秒，启动成功后会自动打开用户端。

脚本会检查并启动尚未运行的前后端，复用已经运行的服务。通过 Windows 任务计划程序在后台运行，关闭浏览器不会停止服务；重启电脑后需要再次启动。

启动失败时查看窗口提示及根目录下的 `startup-logs/`。脚本不会安装依赖、初始化数据库或终止其他占用端口的程序。

## 手动启动：两个 PowerShell 窗口

先启动 MySQL，再分别打开两个 PowerShell 窗口。

第一个窗口启动后端：

```powershell
cd "E:\CodexProjects\AI-Course-Learning-Platform\math-auth-app\server"
& D:\node.exe src.js
```

第二个窗口启动前端：

```powershell
cd "E:\CodexProjects\AI-Course-Learning-Platform\math-auth-app\client"
& D:\npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

两个窗口需要保持打开。按 `Ctrl+C` 停止对应窗口启动的服务。如果提示端口已被占用，先确认是否已经通过一键方式启动。

以上命令使用当前电脑的 Node.js 路径。其他电脑安装 Node.js 并配置 PATH 后，可分别使用 `node src.js` 和 `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort`。

## 新环境安装与配置

已有可用环境不需要重复初始化数据库或覆盖配置。

1. 安装 Node.js、npm 和 MySQL。前端使用 Vite 8，Node.js 需满足其版本要求（20.19+ 或 22.12+），建议使用受支持的 LTS 版本。
2. 在新的 MySQL 环境中执行 `database/schema.sql`，创建 `math_path` 数据库和基础表。后端启动时会检查并补充部分功能表结构，因此数据库账号需要相应建表、改表权限。
3. 在 `server/` 和 `client/` 目录中分别运行 `npm install`。
4. 将 `server/.env.example` 复制为 `server/.env`，再填写本机数据库连接与随机生成的 JWT 密钥。模板中的值仅为占位内容，不能直接作为实际配置。已有环境请保留原 `.env`，不要覆盖。

首次安装时，在项目根目录的 PowerShell 中执行：

```powershell
Copy-Item server/.env.example server/.env
```

配置字段如下：

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_USER=你的数据库用户名
MYSQL_PASSWORD=你的数据库密码
MYSQL_DATABASE=math_path
JWT_SECRET=替换为随机生成的长密钥
PORT=8005
CLIENT_ORIGIN=http://127.0.0.1:5173
```

5. 按前述方式启动前后端，检查网页能否正常打开。
6. 使用已有管理员账号进入管理端，在「服务状态」中配置文字 AI、邮件及生图服务。注册、验证码登录和找回密码需要邮件服务可用。新数据库中的管理员账号需要单独初始化；项目不提供公开的默认管理员密码。

`JWT_SECRET` 同时用于相关服务密钥的加密，已有环境不要随意更换。`.env` 中的实际密码和服务密钥应私下保存，不写入 README 或公开仓库。

## 技术与目录

| 部分       | 技术 / 用途                                          |
| ---------- | ---------------------------------------------------- |
| 前端       | React、Vite、CSS、Tiptap 富文本编辑器                |
| 后端       | Node.js、Express、Zod                                |
| 数据与鉴权 | MySQL、JWT、bcrypt                                   |
| AI 服务    | 可配置的文字 AI 接口，以及火山引擎 Seedream 配图服务 |
| 文档处理   | OfficeParser、PDF 处理与浏览器渲染工具               |

```text
math-auth-app/
├─ client/              前端页面、组件和样式
├─ server/              后端接口、任务与服务配置
│  ├─ .env              本机配置，不公开
│  └─ storage/          上传资料、预览、图片与备份等运行数据
├─ shared/              前后端共享逻辑
├─ database/schema.sql  基础数据库结构
├─ docs/                产品规划与专项说明
├─ startup-logs/        一键启动产生的日志
├─ start-site.cmd       Windows 一键入口
├─ start-site.ps1       启动检查与调度
└─ site-service.ps1     后台服务运行脚本
```

前端构建：在 `client/` 中运行 `npm run build`，输出为 `client/dist/`。构建产物不包含后端、数据库或上传资料。

后端测试位于 `server/*.test.mjs`，多数集成测试需要 MySQL、已配置的测试环境及运行中的后端。不要在不了解测试影响时对重要数据直接运行全部测试。

## 代码维护

根目录使用固定版本的 Prettier，格式规则见 `.prettierrc.json`，缩进和换行规则见 `.editorconfig`。

```powershell
# 在项目根目录安装维护工具
npm install
# 检查格式；需要整理时运行 npm run format
npm run format:check
# 在 server 目录运行后端测试，依赖已配置的数据库和运行中的后端
npm --prefix server test
# 运行前端与共享逻辑的单元测试
node --test client/src/*.test.mjs shared/*.test.mjs
```

PDF 原页阅读需要 Poppler。后端优先使用 `PDFINFO_PATH`、`PDFTOPPM_PATH` 指定的可执行文件，也支持 `POPPLER_BIN` 目录和系统 PATH；Windows 上可以复用本机桌面运行时已提供的工具。调整工具配置后需重启后端。

## 数据保存与备份

课程、章节、笔记、练习、错题和计划等数据存储在 MySQL；原资料、笔记图片、课程封面和章节配图等文件位于 `server/storage/`。资料和预览目录可以通过 `UPLOAD_DIR`、`PREVIEW_DIR` 调整。

仅复制代码无法完整迁移学习数据。迁移时应同时保留数据库、实际文件目录和私下保存的配置。浏览器本地草稿及对话也应另行确认，不要默认已包含在服务端备份包内。

管理端提供备份功能；重要备份应下载并另存，恢复前先在独立环境核验。具体存储位置与手动备份方法见 [备份与恢复](docs/备份与恢复.md)。

## 常见问题

| 情况                     | 检查方式                                                                         |
| ------------------------ | -------------------------------------------------------------------------------- |
| 网页打不开               | 确认前端和后端已启动，地址为 `127.0.0.1:5173`                                    |
| 页面打开但数据加载失败   | 确认后端 8005 端口及 MySQL 正常，查看后端错误提示                                |
| 数据库提示 Access denied | 核对 `server/.env` 中的用户名、密码和 MySQL 账号权限                             |
| 提示端口已占用           | 检查是否重复启动；一键启动和手动启动不需要同时使用                               |
| 找不到 node 或 npm       | 本机可使用上述 `D:\node.exe`、`D:\npm.cmd`；其他电脑检查安装与 PATH              |
| 注册或验证码失败         | 在管理端检查邮件服务配置和发送结果                                               |
| AI 无法生成内容或图片    | 检查对应服务是否启用、连接结果、模型权限、余额和平台限额；文字与图片服务分别配置 |
| 忘记数据库密码           | 查看私有的 `server/.env` 中 `MYSQL_PASSWORD`，不要把整个配置文件公开发送         |

前端接口统一由 `client/src/api-base.mjs` 配置，默认通过 Vite 代理访问 `/api`；需要独立 API 地址时可配置 `VITE_API_BASE`。当前启动方式仍面向本机开发，公网部署还需要单独配置静态文件服务、反向代理与访问保护。
