# 导入与图片分析提速验证

2026-10-19 本机单次对比，使用程序生成的测试 PDF。

| 场景                                |  优化前 |  优化后 | 完整性检查         |
| ----------------------------------- | ------: | ------: | ------------------ |
| 120 页可复制文字 PDF，读取全部文字  |  581 ms |  413 ms | 120 页标记均保留   |
| 9 页 PDF 图片分批分析，同一 AI 接口 | 3166 ms | 1547 ms | 9 页上下区全部返回 |

导入对比采用同一份文件：原方案通过 OfficeParser 构造文档结构后转文字，新方案在独立线程直接提取 PDF 自带文字。扫描内容继续保留在原图中，章节目录生成时再识别图片。

图片分析对比同时包含两项变化：并行批次从 2 增至 3，中间结果改为紧凑数组，仅返回分区标题和主题。原页分区、图片分辨率和最终阅读原图保持一致。实际并行度受平台总并发限制，给问答预留名额。

以上是单次测试记录，整本资料的耗时还受页数、内容复杂度与服务响应影响。已验证目录按课程资料、模型和整理要求缓存；相同输入可复用，要求变化则重新分析。

删除课程会取消在途导入及 AI 请求，停止后续保存。后台导入队列、刷新后的进度恢复与失败重试机制继续保留。

复测命令，在项目根目录运行：

```powershell
cd server
node benchmarks/pdf-speed.mjs
# 加 --ai 会将自建测试图片发给当前配置的 AI 接口，约 6 次小请求并消耗服务额度。
node benchmarks/pdf-speed.mjs --ai
```
