# PDF 导入与分章稳定性

## 已确认的失败原因

270 页资料已完成导入，失败发生在后续 AI 分章，不能把图片识别批次完成理解为整个目录已经保存。

| 环节           | 原有问题                                 | 处理方式                                                                 |
| -------------- | ---------------------------------------- | ------------------------------------------------------------------------ |
| 图片分批识别   | 少数批次回答被截断，或返回结构不符合约定 | 紧凑 JSON、非思考模式、受控输出预算；格式失败重试后拆成逐页识别          |
| 长资料汇总     | 受限输出预算也可能被思考过程消耗         | 资料压缩显式使用非思考模式；截断结果丢弃后有限重试，不把残缺回答当作正文 |
| 目录生成与采用 | 最多 20 章的旧校验导致最终汇总失败       | 生成、缓存校验、采用统一最多 300 章，保留全部页码校验                    |
| 最终进度       | 图片已识别完成，但界面仍停留在批次数     | 分别显示目录汇总、生成与页码校验阶段                                     |

## 本轮补充的保护

- 目录整体保存在同一事务中。插入失败或保存途中中止时回滚，旧草稿不会被半份新目录替换。
- 保存前锁定课程并核对资料版本。生成期间资料被删除或替换时，本次结果不再保存。
- 删除资料后中止相关课程的在途生成；其他课程的任务不受影响。
- 采用目录也锁定课程，防止重复提交并发追加章节；拒绝重复草稿编号和丢失图片映射所需的草稿编号。
- 图片页码采用服务端保存的映射，不能由前端提交的页码替换。
- 同一原页的并发请求共享渲染。图片写入临时目录，验证 PNG 头部和结束标记后再发布；损坏缓存重新生成，失败后清理临时文件并释放请求锁。
- 删除资料时清理其原页缓存，保留其他资料的文件。
- 空回答可以有限重试；断连、超时、鉴权和服务返回非 JSON 数据会明确报错，不通过不断拆页重复请求来尝试解决。
- 主动取消保持取消语义。已完成的图片识别缓存保留，后续用户手动重试时可以复用。

## 验证范围

独立回归测试使用合成资料与模拟 AI，覆盖 30 章、270 页的生成—缓存—采用流程，以及遗漏页码、超量目录、输出截断、空回答、断连、取消、保存失败、资料变更、重复采用、图片并发和损坏缓存恢复。测试已纳入 GitHub 自动检查。

另有显式启用的 `server/chapter-generation.integration.test.mjs`：使用独立临时 MySQL 表验证真实事务回滚和同时采用目录，只清理本次创建的测试表，不修改用户课程，不调用外部 AI。本机还使用一页合成 PDF 验证了实际 Poppler 渲染及图片缓存发布。

这些检查验证流程和数据一致性，不代表模型对任意新教材的标题及知识划分都会准确。一次图片分章仍限制为合计 300 页；支持图片输入的模型、可用的服务额度和 Poppler 是运行前提。模型按当前用户及平台设置选择，不自动替换模型。

后台导入完成后可离开页面；文件尚未上传完成时仍需保留浏览器页面。服务重启会恢复未完成的导入，AI 生成任务则提示用户手动重试，不擅自继续付费请求。
