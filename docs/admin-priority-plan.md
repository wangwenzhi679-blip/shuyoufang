# 管理端重点完善方案

更新日期：2026-10-10  
适用项目：数有方——个人自主学习平台  
文档状态：已批准开发。任务处理、课程与资料暂停恢复、预览后台修复及管理员修改密码已实现。数据备份、独立恢复验证和运行限制继续推进。

## 一、目前的判断

管理端已有账号停用与恢复、课程和资料查询、公告管理、AI 与邮件服务配置、服务检查及操作日志。管理员可以控制账户和服务，但对异常任务、问题资料以及数据恢复的处理能力仍不完整。

下一阶段优先补齐“发现问题之后能够处理”的能力。继续保留个人自主学习定位，不增加教师、班级或作业发布体系。

| 优先级 | 重点               | 解决的问题                             | 本阶段建议                               |
| ------ | ------------------ | -------------------------------------- | ---------------------------------------- |
| 1      | AI 任务处理        | 任务卡住或失败后，管理员只能查看       | 任务详情、取消、失败重试                 |
| 2      | 课程与资料处置     | 问题内容无法暂停使用，预览损坏无法修复 | 暂停与恢复、原因说明、预览修复           |
| 3      | 数据备份           | 误操作或故障后缺少可靠恢复依据         | 手动备份、完整性检查、独立恢复验证       |
| 4      | 管理权限与运行限制 | 敏感操作权限过于笼统，资源使用缺少约束 | 管理员密码、权限分级方案、上传与生成限制 |

建议先开发第 1、2 项，再推进第 3、4 项。若近期准备提供给其他人长期使用，应将第 3 项提前到正式开放之前。

## 二、AI 任务处理

### 管理员可以做什么

- 查看任务类型、所属账号、课程与章节、状态、开始时间、可取得的进度和失败原因。
- 取消正在生成的异常任务，填写处理原因。
- 对满足条件的失败任务发起重试，并查看原任务与新任务的关联。

### 具体规则

1. 取消必须由后端执行，学习端同步显示“已由管理员取消”。已经完成或进入无法中止的保存阶段时，明确说明当前状态。
2. 被取消任务即使稍后收到 AI 响应，也不能继续写入结果。
3. 重试创建新任务，不修改原失败记录；双击或多窗口重复操作不能创建多份任务。
4. 重试前检查账号状态、课程和章节是否存在、原输入是否保留、资料版本是否变化。条件不满足时说明原因，由学习者重新发起。
5. 重试成功后仍由学习者查看和采用，不能直接覆盖其章节、笔记、练习或计划。
6. 默认展示运行信息，不在任务列表展开用户提问、笔记和完整生成正文。

### 完成标准

管理员能取消实际运行任务、重试符合条件的失败任务；用户端同步状态；取消后没有迟到写入；日志记录操作者、原因、时间和处理结果。

## 三、课程与资料处置

### 管理员可以做什么

- 查看问题课程和资料的所属账号、文件状态、预览状态及处理记录。
- 暂停某门课程或某份资料的使用，填写原因；问题解决后恢复。
- 对原文件存在、格式受支持的资料重建预览。

### 具体规则

1. 暂停采用可恢复状态，第一阶段不增加一键永久删除课程或原文件。
2. 课程暂停后，后端阻止该课程的新阅读、文件访问和生成请求；资料暂停后，阻止该资料的下载、预览及作为新 AI 请求的输入。
3. 用户能够看到暂停原因和时间。其他正常课程继续使用，已有笔记、练习记录保留。
4. 已经发往外部 AI 的内容无法撤回。与被暂停内容有关的任务应尽可能取消，并阻止新的结果采用或写入；具体联动随任务处理能力一起实现。
5. 恢复时保留原章节、学习进度和文件关联，不要求用户重新导入。
6. 预览重建后台执行，新预览成功后再替换旧版本；失败保留原来可用的版本。原件缺失时提示重新上传，不能显示无效的修复按钮。
7. “未提取到文字”不等于文件损坏，扫描件、公式和图片资料仍可能正常阅读。
8. 是否允许管理员查看资料正文，需要单独确定。本阶段默认先提供状态与故障信息，不增加任意浏览用户私有内容的入口。

### 完成标准

暂停与恢复在真实接口生效，不能只隐藏按钮；用户能理解原因；恢复后关联数据完整；预览修复不会损坏原件。

## 四、数据备份

### 管理员可以做什么

- 创建手动备份，查看进度、大小、完成时间及校验结果。
- 下载有权限访问的备份包。
- 查看备份失败原因，重新创建。

### 具体规则

1. 备份包含数据库、上传原文件、笔记图片及文件清单，确保数据库记录与文件相互对应。
2. 备份存放在明确配置的 E 盘目录；失败或不完整的备份不能标记为可用。
3. 密钥不通过普通下载包明文导出。加密服务配置恢复所依赖的服务器密钥，需有单独的保管和恢复步骤。
4. 先在独立环境验证恢复，确认账号、课程、资料和学习记录可用，再设计正式环境恢复按钮。
5. 正式恢复会影响现有数据，后续必须提供恢复范围、影响说明和确认流程。

### 完成标准

能够从备份在独立环境恢复出可正常使用的数据。仅能下载文件，不能算备份能力验收完成。

## 五、管理权限与运行限制

### 第一批建议

- 管理员修改自己的密码：校验当前密码，修改成功后撤销旧登录，要求重新登录。
- 上传限制：单文件大小、每批数量，数值由后端校验并持久保存。
- AI 并发限制：限制同时运行的生成任务数，超限时明确排队或拒绝规则，避免无限等待。
- 问答与后台生成分别设置暂停状态；暂停新请求不自动承诺取消已有请求。

### 权限分级建议

现有 `admin` 作为超级管理员候选，后续经确认迁移。若目前始终只有一个管理员，可以先完成上述第一批，暂缓多管理员账户界面。

| 权限                           | 超级管理员 | 普通管理员（建议） |
| ------------------------------ | ---------- | ------------------ |
| 查看运行情况、处理任务         | 允许       | 允许               |
| 暂停和恢复普通用户、课程、资料 | 允许       | 允许               |
| 管理公告                       | 允许       | 允许               |
| 修改 API 密钥、邮件配置        | 允许       | 不允许             |
| 下载备份、执行正式恢复         | 允许       | 不允许             |
| 创建管理员、变更权限           | 允许       | 不允许             |

权限必须在后端接口校验，隐藏菜单不能代替权限控制。禁止删除或停用最后一个可用的超级管理员。

### 完成标准

普通管理员无法通过直接请求执行越权操作；密码和权限变化后旧登录按规则失效；限制重启后仍有效，界面与实际执行一致。

## 六、统一操作要求

- 取消任务、重试、暂停、恢复、删除、修改设置均使用明确的确认弹窗；取消和确认按钮同尺寸，位于右下角。
- 重要操作记录管理员、对象、原因、时间和结果；日志不保存密码、密钥和无关用户正文。
- 后台任务不阻塞其他页面，刷新后可以继续查看。
- 多窗口操作检查数据版本；失败保留填写内容并说明原因。
- 日期统一中文年月日展示；缺失信息显示“未记录”，不补造历史数据。

## 七、暂缓事项

复杂统计大屏、自动计费、精细到每个按钮的自定义角色、教师端、班级管理，以及未经恢复验证的一键恢复或永久清空，不列入本轮重点。

## 八、阅读后的决策

建议优先确认：

1. 是否按“任务处理 → 内容处置 → 数据备份 → 权限与限制”推进。
2. 内容处置是否采用“暂停与恢复”，先不提供永久删除。
3. 是否只有自己使用管理员账号；若是，多管理员分级界面可以后置。

已按批准范围开发；实现进度见文档开头及管理端规划记录。未完成的备份、恢复验证和运行限制不标记为已完成。

## 管理端运行限制与基础备份（2026年10月11日）

- 管理员可配置资料单文件大小（1—100MB）、单次数量（1—20个）及实际模型请求并发数（1—16）；超额模型请求排队，支持取消，异常后释放并发名额。
- AI 问答与 AI 生成各有暂停开关，禁止新任务；已开始的任务继续执行。学习端生成和管理员重试均检查开关。
- 设置保存到 MySQL，使用版本检查防止覆盖，并记录修改原因；重启后保持。
- 数据备份保存数据库、原资料、笔记图片和可用预览，下载为 ZIP；不包含部署环境文件。服务密钥仍为加密状态，部署环境配置需另外保管。
- 备份与恢复验证后台运行，可切换页面；重启中断标记失败。恢复验证新建独立临时数据库，核对数据内容、关联完整性及文件校验，最后清理临时数据库，不覆盖在线数据。
- 原资料或笔记图片缺失、备份期间文件变化、校验失败均不标记成功；不提供在线覆盖恢复按钮。创建、验证使用原因确认弹窗，取消和确认按钮同尺寸。
- 本轮运行限制、基础备份和独立恢复验证已实现；多管理员分级和复杂恢复工作流继续暂缓。
