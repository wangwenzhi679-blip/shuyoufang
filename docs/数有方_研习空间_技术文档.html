01 第一章 项目概述 (Project Overview)

1.1 研发背景与行业研习痛点深度剖析

在当今高等教育与终身学习时代，知识的更新迭代呈现爆炸式增长。大学生、科研工作者及各行各业专业学习者，普遍面临从“被动接受标准化课程”向“以个人目标为驱动的自主深度研习”转型。然而，审视当前主流的学习工具链与在线教育基础设施，个人自主研习仍面临诸多难以逾越的结构性痛点：

核心痛点维度 传统学习模式与工具现状 数有方 · 研习空间的解决范式
资料孤岛与知识割裂 学习资料（教材PDF、教师PPT课件、历年题库Word、网页考点）散落于本地磁盘与网盘中，阅读、提问、记笔记、做题依赖多个独立软件频繁切换，知识上下文无法连续沉淀。 以“个人资料为第一原点”，一站式完成资料导入、AI目录抽取、章节对齐、原页阅读、交互笔记、测验与计划，形成完整的数据与认知链路。
理工科复杂公式失真 市面常规文档转换与文本提取工具，遇到高等数学、线性代数、力学等学科中的复杂矩阵、多重积分、分式和特殊符号时，极易退化为方块乱码、漏字符或排版崩溃。 首创“视文双轨自适应阅读引擎”：文本流负责语义索引与大模型上下文供给；Poppler 高保真原页渲染引擎负责矩阵与公式的像素级原貌展现。
通用大模型漂移与幻觉 直接使用公网通用聊天机器人提问时，AI 缺乏特定教材的边界约束，回答泛泛而谈、答非所问，甚至捏造不存在的定理与计算公式，且无法将回答直接沉淀为试卷或笔记。 构筑“强约束课程知识沙箱”：所有 AI 问答、总结与出题均以学习者绑定的章节资料为硬约束，提供置信依据反查，并支持回答一键转笔记、一键出题。
学练脱节与遗忘周期失控 看完资料缺少即时自测，即使做了习题也缺乏针对错题的科学复习规划；市面错题本多为机械截图，无法结合遗忘曲线自动调度复习周期。 实现“认知科学级学练测闭环”：根据章节资料智能生成多题型测验，交卷即判分；错题一键入库，并基于改进艾宾浩斯遗忘曲线（1, 3, 7, 14, 30天）动态派发任务。

1.2 产品定位与系统核心建设目标

数有方 · 研习空间（Shuyoufang Study Space）定位于专为大学生与高阶个人自学者打造的“以资料为原点的深思型 AI 自主研习平台”。 平台不仅提供强大的文档解析、智能伴学、自动测验与间隔复习功能，更在人机交互层面摒弃冷硬浮夸的商业化教培设计，独创融合“纸色、墨韵、青绿、朱红”的中式研习空间人文美学，使学习者能够在宁静沉浸的氛围中开展深度研读与知识内化。

数有方系统四大核心技术工程目标
  1. 工程高可用与秒级启动：构建低耦合的前后端拓扑结构，具备跨平台部署与自动化调度能力，确保服务冷启动稳定、运行状态自愈、接口秒级响应。
  2. 长上下文低耗推理：针对数十万字的大型学术资料，建立分层切片机制与双层 SHA-256 缓存网格，实现大模型调用成本降低 60% 以上，响应速度提升 3 倍。
  3. 信号级任务可控性：全栈打通 AbortController 中断信号链与 MySQL 任务持久化状态机，实现 AI 出题、目录梳理长耗时任务的无感后台化、防迟到写入与秒级平滑取消。
  4. 严谨的结构化认知校验：在 AI 出题与解析环节建立强类型模式校验（Zod Schema）与二级 AI 逻辑核对机制，杜绝错题、漏选、选项错乱等大模型固有幻觉。

3.2 前端工程架构与中式现代研习交互系统

前端基于 React 19 与现代化构建工具 Vite 8 构建。在工程架构上，系统摒弃厚重的第三方 UI 组件库，全面采用原生模块化 CSS 与语义化 CSS Custom Properties，从而实现对渲染管线与中式研习空间视觉风格的像素级掌控：

  • 中式色彩语义体系：以宣纸底色（#faf8f5）、墨黑正文（#0f2744）、青绿主色（#2e6b5e）、朱红警示（#b83b3b）构建统一视觉规范，营造清雅、凝神的学术沉浸感。
  • 轻量化组件解耦：采用按需加载与单例弹窗总线，用户端（学习首页、我的课程、章节研读、AI 助手、错题复习、学习计划）与管理端（运营大屏、用户管理、服务配置、任务监控）完全物理解耦，避免样式污染与权限泄露。
  • Tiptap 富文本微内核：深入扩展 @tiptap/core，接入 StarterKit、UniqueId、Image、Placeholder 扩展，深度定制字号指令（12px～32px 严格白名单），实现无多余空段落的精密文档渲染。
  • 断点记忆与无感草稿自愈：对未交卷的练习答案与未落库的笔记草稿，实施 LocalStorage 本地优先策略，结合服务端接口同步，有效抵御页面误刷、断网和误触返回。

    "UPDATE course_generation_jobs SET status='saving' WHERE id=? AND status='running'",
    [id]
  );
  if (!changed.affectedRows) throw new Error('任务已被取消或已被抢占');
};
任务状态机四阶段变迁与防迟到写入保障

任务生命周期划分为四个原子状态：running（执行中） → saving（落库前校验锁） → done（完成并持久化） / failed（失败告警） / cancelled（用户主动中断）。 当用户在客户端点击“取消”时，服务端立即触发 controller.abort() 并将状态置为 cancelled。即使底层网络请求迟到返回，在进入 saving 时会因 affectedRows === 0 判定任务已终止，从而彻底杜绝陈旧结果非法覆盖当前业务数据的并发隐患。

  • 换行回溯断句切块：splitContext(text, 12000) 绝不在词句中央机械硬截断，而是从 12,000 字符末尾向前寻找最近的换行符 （回溯界限至 6,000 字符处），确保每个 Chunk 保持完整的段落与命题完整度。

在 server/pdf-outline.js 中，系统首创了“12% 边缘重叠动态拓扑裁切算法（regionCrop）”：

图 4-2 12% 边缘重叠动态拓扑裁切算法原理解析图
// server/pdf-outline.js 12% 重叠区域裁切核心算法
export function regionCrop(box, angle, zone) {
  const top = zone === 'top';
  const rotation = ((angle % 360) + 360) % 360;
  // 核心机理：上下各切取 56% 页面高度，在物理空间形成 12% (56% + 56% - 100%) 的重叠保护带
  if (rotation === 90 || rotation === 270) {
    const fromRight = rotation === 90 ? !top : top;
    return { x: box.x + (fromRight ? box.width * 0.44 : 0), y: box.y, width: box.width * 0.56, height: box.height };
  }
  const fromUpper = rotation === 180 ? !top : top;
  return { x: box.x, y: box.y + (fromUpper ? box.height * 0.44 : 0), width: box.width, height: box.height * 0.56 };
}

4.3.3 优化策略三：强契约模式（Zod Schema）与二级 AI 交叉核对机制

在智能出题场景中，大语言模型存在两个顽固的固有幻觉： ① 格式幻觉：如少给选项、非 A-D 编号、选项重复； ② 逻辑矛盾幻觉：特别是在多选题（Multiple-Choice）中，大模型生成的“答案解析”中逐条明确承认“A、B、C 选项均符合题意”，但在“正确答案”字段中却仅仅粗心列出了 ["A", "B"]，导致判分出现致命偏差。

数有方为此建立了双重防护网：

防幻觉双重防御体系：模式强校验 + 二级 AI 选项交叉核对
  1. 第一道防线（静态结构校验）：使用 Zod 模式解析器对大模型返回的 JSON 执行毫秒级语法校验。强制要求单选题必须有且仅有 A、B、C、D 四个非空选项，答案严格属于 enum(['A','B','C','D'])；多选题答案数组长度必须 ≥ 2 且按字母升序排列。任何语法不合格结果直接拦截，不予落库。
  2. 第二道防线（二级 AI 逻辑核对）：针对所有生成的多选题，后端在入库前自动触发专门的二级核对器（verifyMultipleChoiceQuestions）。向大模型发送包含题目、4个选项及候选答案的核对 Prompt，逐个选项判别正误。若核对器发现答案列表与逐项逻辑不一致，自动以核对器的精确结果更新最终答案与解析；若核对失败，整张试卷拒绝持久化。实测将多选题答案差错率彻底降至 0。

4.3.4 优化策略四：Token 超限自适应补偿重试与熔断降级

在大模型生成超长篇幅总结或试卷时，常因达到云端 max_tokens 限制而被硬截断，导致返回格式残缺（如 JSON 缺少右大括号）。 系统在客户端和 Node.js 端封装了错误分类感知拦截器：精确捕获 AI_OUTPUT_LIMIT 错误码，在检测到截断时立即自动向模型发送追问补偿提示词（“请重新精简整理，只保留核心知识范围，控制在 1200 字以内，必须覆盖片段末尾”），并在单次生成中自动补偿重试一次。

当外部模型出现余额耗尽（402）、网关超时（504）或第三方限频（429）时，系统自动启动优雅降级策略： 历史章节总结与已缓存题目无缝回退呈现；配图失败自动使用学术几何占位图，且前台明确提示具体运维诊断建议，绝不因 AI 外部偶发故障而中断正常研读。
