# 学习笔记功能规划

增强版方案见 [学习笔记增强规划](learning-notes-enhancement-plan.md)。基础版本已实现，增强版六项功能尚待开发；下文“第一版”边界保留作为已交付版本记录。

- 更新日期：2026-10-04
- 项目：数有方——基于 AI 的课程学习与智能练习平台
- 面向用户：个人自主学习者
- 当前状态：第一版已实现（2026-10-04）

## 1. 功能目标

用户在学习章节时记录自己的理解，也可以摘录 AI 总结和问答内容，整理成与章节关联的个人笔记。

使用流程：阅读章节资料 → 提问或查看总结 → 整理笔记 → 练习巩固 → 回顾笔记。

## 2. 第一版功能范围

| 功能         | 具体规则                                           |
| ------------ | -------------------------------------------------- |
| 章节笔记     | 每个章节一份笔记，首次打开为空，可以直接输入       |
| 编辑笔记     | 支持普通文字、换行、粘贴和分段                     |
| 自动保存     | 编辑后自动保存，显示保存状态，切换章节或刷新后恢复 |
| 摘录 AI 总结 | 预览并编辑摘录内容，确认后追加到当前章节笔记末尾   |
| 摘录 AI 回答 | 从已完成的回答发起摘录，选择目标章节，确认后追加   |
| 清空笔记     | 二次确认后清空，不删除章节及学习资料               |

第一版保持简单，暂不包含图片笔记、手写、复杂富文本工具栏、分享、导出、独立笔记中心和历史版本恢复。

笔记中的文字摘录不承诺还原 PDF 的矩阵、公式和原始版式。需要保留版式的内容继续通过资料原页阅读。

## 3. 页面和交互

### 3.1 章节内入口

在章节内容区域增加“学习笔记”标签，与现有章节功能并列。切换章节时同步切换笔记。

页面包含章节名称、保存状态、笔记编辑区域和“清空笔记”入口。空白提示为“记下这一章的理解与疑问”。

正文在页面内直接编辑；摘录预览、选择目标章节和清空确认使用弹窗。弹窗沿用现有蓝白风格，取消和确认按钮等宽，放在右下角。

### 3.2 摘录 AI 总结

1. 点击总结旁的“加入笔记”。
2. 弹窗展示目标章节及待摘录内容，允许修改文字。
3. 确认后追加到笔记末尾，与已有内容之间保留空行。
4. 保存成功后提示“已加入笔记”，提供查看笔记入口。

### 3.3 摘录 AI 回答

1. 在已完成的 AI 回答下点击“加入笔记”。
2. 选择课程和目标章节，预览并编辑摘录内容。
3. 确认后追加保存，不覆盖原笔记。

若没有可选章节，提示先创建章节，不自动创建课程或章节。摘录保留来源类型和日期；后续重新生成 AI 内容，不改变已经摘录的文字。

提交期间禁用重复提交。同一来源已摘录时提示用户，避免连续点击造成重复内容。

## 4. 保存与异常处理

- 笔记按账户、课程和章节关联，每章一份，正式内容保存到数据库。
- 输入时保留本地草稿，停止输入约一秒后同步服务器。
- 显示“保存中”“已保存”“保存失败，请重试”等状态，服务器确认后才能显示已保存。
- 网络异常时保留输入及本地草稿，支持重试，不清空编辑区域。
- 切换章节或刷新时恢复该章节内容；存在未同步草稿时优先恢复并提示。
- 摘录追加与自动保存使用版本校验，避免互相覆盖。
- 多窗口修改发生冲突时提示重新加载或保留本地内容，不静默覆盖。
- 章节改名和排序不影响笔记归属；删除章节或课程时，确认提示说明关联笔记也会删除。
- 清空成功后同步清理旧草稿，防止刷新后旧内容重新出现。
- 本地草稿按账户隔离，退出或切换账户后不向其他账户展示。

## 5. 与现有功能的关系

| 现有功能         | 联系                                       |
| ---------------- | ------------------------------------------ |
| 课程管理         | 提供课程和章节归属                         |
| 章节阅读         | 阅读原文后记录理解与疑问                   |
| AI 总结          | 将已有总结摘录为可编辑笔记                 |
| AI 学习助手      | 将选定回答摘录到指定章节                   |
| 章节练习、错题本 | 用户自行记录解题思路，第一版不自动写入笔记 |

## 6. 技术栈与实现规划

沿用项目现有技术栈：React、Vite、CSS、Node.js、Express、MySQL 和 JWT 登录验证。

- 前端：章节笔记编辑区域、摘录弹窗、保存状态及按账户和章节隔离的本地草稿。
- 后端：读取、保存、追加和清空笔记接口，检查登录及课程、章节归属。
- 数据：记录笔记编号、用户编号、课程编号、章节编号、正文、版本号和更新时间；记录摘录来源以识别重复操作。
- AI：摘录使用现有生成结果，不额外调用模型。

## 7. 验收标准

1. 不同章节、不同账户的笔记互不混淆。
2. 输入后可以自动保存，切换章节及刷新后内容可恢复。
3. 网络失败时输入不丢失，恢复后可重试保存。
4. 总结和回答能追加到正确章节，保留原有笔记。
5. 重复点击不重复追加，摘录与自动保存不会互相覆盖。
6. 清空需要确认，取消不修改内容，清空后刷新仍为空。
7. 保存状态真实，多窗口冲突有明确提示。
8. 界面使用简体中文，沿用项目蓝白风格。
