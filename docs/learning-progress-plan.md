# 学习进度与完成标记：功能规划

日期：2026-10-07  
状态：第一版已实现，验证范围与限制见第 9 节。

## 1. 目标与范围

让个人学习者知道课程学到哪里、哪些章节已学完，并连接课程、首页和学习计划。沿用现有蓝白界面和章节目录结构，使用真实保存的数据。

本期包括章节完成标记、课程进度展示、完善继续学习入口、关联计划阅读任务。阅读位置已有基础能力，本期在此基础上接入，不重复建设。

## 2. 页面与操作

| 位置       | 展示与操作                                                          |
| ---------- | ------------------------------------------------------------------- |
| 章节内容页 | 提供“标记已学完”；完成后显示“已学完”，支持取消标记                  |
| 章节目录   | 已学完章节显示小勾和可辨识状态，保持现有目录布局及快速切换          |
| 我的课程   | 课程卡片显示进度条及“已完成 3 / 8 章”；没有章节时显示“尚未添加章节” |
| 学习首页   | 完善“继续学习”，回到上次访问章节及可恢复的阅读位置                  |
| 学习计划   | 将对应章节的阅读任务与章节完成状态关联，区分手动完成和自动完成来源  |

按钮和状态紧凑，不增加大型弹窗。取消完成属于可逆状态切换，可直接操作；请求失败时保留原状态并提示重试。请求处理中防止重复点击。

## 3. 完成标记与计算规则

- 章节是否学完由用户主动标记。打开章节、滚动到底或停留一段时间均不自动算完成。
- 课程进度 = 已完成的当前章节数 ÷ 当前章节总数；百分比取整数，同时展示准确章节数量。
- 无章节时不做除法计算，不显示完成 100%。全部当前章节已完成时显示 100%。
- 新增章节默认为未完成，重新计算课程进度；删除章节后从分子、分母中移除对应记录。
- 修改章节名称或排序不清除完成状态。章节依靠唯一标识关联，不能按名称或序号匹配。
- AI 重新整理目录：保留原章节标识的章节保留状态；真正新建的章节默认未完成，不猜测迁移旧状态。采用目录前说明替换造成的状态影响。
- 状态保存到 MySQL，并按登录账户隔离；刷新、重新登录后读取已保存状态。
- 阅读完成、练习成绩、错题掌握各自记录，互不替代。

## 4. 与学习计划的关联

1. 标记章节已学完时，同步完成本人现有计划中明确关联该章节的阅读任务。
2. 只匹配章节标识与阅读任务类型；练习、笔记、错题任务不受影响。
3. 自动完成记录完成来源和对应章节，手动完成记录保留手动来源。
4. 取消章节完成时，只撤销由该章节标记自动完成的任务，不撤销用户手动完成记录。
5. 用户主动将任务设为完成时，将来源记为手动；任务操作不反向改变章节状态。
6. 新采用的计划中，若阅读任务对应已学完章节，则同步为自动完成；来源同样可追溯。
7. 一个章节对应多份计划时，按同样规则同步各自的阅读任务。删除计划不影响章节进度。
8. 没有明确章节关联的自定义任务不参与自动同步。
9. 章节标记与关联任务更新作为一次一致的数据操作，避免一边成功、一边失败。

## 5. 继续学习与异常情况

- 复用已有最近访问章节和阅读位置；完成标记不覆盖最近阅读位置。
- 即使上次章节已学完，继续学习仍回到上次实际阅读处，不擅自跳到下一章。
- 章节或资料已删除时，进入仍存在的课程并给出简洁提示；课程已删除时更新首页入口。
- 原资料已变化导致位置无法恢复时，打开有效内容的起始位置并提示。
- 章节状态改变后，课程列表、目录、首页和计划重新获取或同步数据，避免显示旧进度。

## 6. 实现约束

沿用现有 React 前端、Node.js 后端和 MySQL 数据库。开发前核对现有章节、阅读记录及计划任务数据结构，再确定字段与接口，不将规划写成已存在的接口。

保存账户与章节关联、完成状态或完成时间；计划任务记录完成来源。接口必须验证所属账户，重复提交同一目标状态应得到一致结果，数据库变更兼容已有课程和手动完成任务。旧章节没有完成记录时默认未完成，旧计划已完成记录按手动完成保护。

## 7. 验收标准

- 标记与取消后，章节目录、课程进度同步变化；刷新及重新登录后状态保留。
- 0 章、部分完成、全部完成、新增和删除章节均正确计算。
- 章节改名和排序后完成标记仍对应原章节；重新生成目录不错误继承状态。
- 同一章节的阅读任务自动完成；取消时仅撤销自动完成，手动完成不变。
- 练习、笔记和错题任务不被误同步；多份计划及新采用计划符合关联规则。
- 继续学习恢复现有阅读位置，删除和资料变化时有有效回退。
- 网络失败不显示虚假成功，连续点击不造成重复或互相覆盖。
- 不同账户不能读取或修改彼此的进度。
- 在实际页面核对按钮、进度条、目录状态和小屏布局，并记录实际验证结果。

## 8. 暂不纳入本期

学习时长计时、连续打卡、能力雷达图、AI 自动判断掌握程度与奖励体系暂不开展。首页整体重新排版仍是独立后续建议。

## 9. 第一版实现记录（2026-10-07）

- MySQL 章节新增 completed_at 字段，旧章节默认未完成；课程查询统计完成章节数，章节查询返回保存状态。
- PATCH /api/courses/:courseId/chapters/:chapterId/progress 验证账户和章节归属，事务保存完成状态与关联计划任务。重复完成保持原完成时间，不重复增加计划版本。
- 章节内容页增加完成/取消按钮，处理保存中和失败提示；目录显示完成勾，课程卡片和首页继续学习显示数量与进度条。更新后重新读取课程列表、章节和计划。
- 计划任务以 completionSource 区分 chapter 和 manual；旧完成记录作为手动保护。取消章节只撤销 chapter 来源的阅读任务，练习和笔记任务不变。新采用或保存计划时同步已学完章节的新增阅读任务。
- 当前采用 AI 目录会删除原章节并新建目录，完成状态不继承；采用弹窗明确说明影响。改名和排序保留原章节标识及状态。
- 继续学习沿用已有章节访问和阅读位置恢复，新增首页课程进度展示；本轮未重新逐种资料格式验证阅读恢复。
- 专项测试通过：数据保存、账户隔离、无效输入、重复操作、计划自动完成与取消、手动完成保护、练习不误同步、删除章节后的统计。
- 原学习计划回归通过：后台生成、采用、并发版本冲突、手动完成、保留历史完成、权限与删除章节处理。前端构建通过。
- 浏览器临时账户验证标记、目录勾、刷新保留、课程 1/2 进度和取消；临时账户验证后已清理。
- 未逐项完成网络故障模拟、小屏视觉验证及新采用已完成章节计划的浏览器验证。现有笔记 PDF 导出问题为之前记录的独立问题，本轮未修复。

### 2026-10-08 每章阅读百分比

章节目录分别显示阅读进度。按本章内容最远阅读位置计算并保存到现有阅读记录，往回阅读不会降低进度；刷新或切换章节后恢复。阅读位置最高显示 99%，标记已学完显示 100%。没有可滚动内容时不自动认定学完。进度表示阅读位置，不代表知识掌握程度；整份原资料的分页阅读不计入章节比例。学习计划的百分比继续表示任务完成比例。
